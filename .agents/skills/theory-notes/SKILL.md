# Теоретические конспекты PTROTHB

Пиши по-русски и ориентируй материал на повторение перед собеседованием.

## Граница изменений

- Объясняй тему в чате, если пользователь не просил создать или изменить файл.
- Создавай или редактируй файл в `theory/` только по явной просьбе.
- Не изменяй другие конспекты, код проекта и `main.go` без отдельного запроса.

## Имя и объём

- Для новой нумерованной темы используй следующий свободный номер: `theory/<N>. <Тема>.md`.
- Заголовок H1 должен совпадать с названием темы без номера.
- Давай достаточный базис для собеседования без превращения конспекта в учебник.
- Расшифровывай термин при первом появлении и сразу объясняй его простыми словами.

## Типичная структура

Подбирай только полезные разделы, обычно в таком порядке:

1. Определение и практический смысл темы.
2. Основные понятия и механизм работы.
3. Схема или последовательность процесса, если она делает материал понятнее.
4. Сравнение близких понятий в таблице.
5. Практический пример, особенно применимый к Go/backend.
6. Типичные ошибки и нюансы.
7. Короткий блок «Что важно на собеседовании».
8. Итоговая шпаргалка «Что важно запомнить».
9. Источники.
10. Ровно два подходящих видео; минимум одно должно быть на русском языке.

Не создавай пустые разделы ради шаблона.

## GitHub-совместимость

- Используй GitHub Flavored Markdown.
- Для схем предпочитай fenced-блоки `mermaid`, поддерживаемые GitHub Preview.
- Для статических изображений используй относительные пути к файлам репозитория и понятный alt-текст.
- Не вставляй локальные абсолютные пути, `file://`, iframe, JavaScript, интерактивный HTML или директивы Codex `visualize`: они не работают в GitHub Preview.
- Схема должна дополнять объяснение, а не повторять большой фрагмент текста.
- Проверяй Mermaid на простоту синтаксиса: короткие идентификаторы узлов, подписи в кавычках при наличии знаков пунктуации, без экспериментальных возможностей.

## Источники и качество

- Если пользователь дал ссылки, прочитай их и используй как основу, но не копируй текст дословно.
- Для меняющихся или спорных сведений проверяй актуальные первичные источники.
- Исправляй найденные упрощения и неточности, не перенося их в конспект как факты.
- В конце добавляй раздел `## Источники` с прямыми ссылками на реально использованные материалы.
- После источников добавляй `## Видео для закрепления` с двумя ссылками и пометками языка (`рус.` / `англ.`) и содержания.

## Стиль

- Пиши короткими абзацами, списками и таблицами; избегай длинных стен текста.
- Выделяй жирным только ключевые мысли.
- Используй термины последовательно и не подменяй точные определения аналогиями.
- В примерах кода показывай только ту часть, которая объясняет тему.
- Отделяй обязательный базис от углублённых деталей.
