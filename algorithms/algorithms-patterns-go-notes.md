## Главная мысль

Не запоминай решения отдельных задач. Запоминай:

1. **Гринфлаги** — слова и ограничения в условии, указывающие на паттерн.
2. **Инвариант** — что остаётся истинным на каждой итерации.
3. **Механику перехода** — почему можно сдвинуть указатель, границу, окно или состояние.
4. **Оценку сложности** — почему каждый элемент обрабатывается один раз или почему нужна сортировка.

На собеседовании двигайся так:

1. Назови наивное решение и его сложность.
2. Найди повторную работу: повторные суммы, повторный поиск, повторный обход.
3. Спроси, что в условии даёт структуру: сортировка, непрерывный отрезок, `in-place`, зависимости, минимум шагов.
4. Выбери паттерн и сформулируй инвариант до написания кода.
5. Проверь пустой ввод, один элемент, границы и дубликаты.

## Быстрая карта выбора

| Сигнал в условии | Куда смотреть |
|---|---|
| Отсортированный массив, палиндром, сужение диапазона | Два указателя с краёв |
| Два массива/строки/списка | По указателю на каждую последовательность |
| Изменить массив `in-place`, сохранив порядок | Быстрый и медленный указатели |
| Непрерывная подпоследовательность | Скользящее окно |
| Частоты, соответствия, «видели ли раньше» | `map` / `set` |
| Интервалы, расписания | Сортировка интервалов или sweep line |
| Отсортированность + монотонный предикат | Бинарный поиск |
| Ближайший больший/меньший | Монотонный стек |
| Много запросов суммы/агрегата | Префиксные значения |
| Голова связного списка создаёт особый случай | Dummy-узел |
| Все комбинации | Перебор / backtracking |
| Ответ собирается от детей к родителю | DFS по дереву снизу вверх |
| Состояние передаётся от родителя детям | DFS сверху вниз |
| Минимум рёбер/ходов в невзвешенном графе | BFS |
| Компоненты/острова/области | DFS или BFS + `visited` |
| Зависимости и порядок выполнения | Топологическая сортировка |
| Оптимум/число способов из меньших подзадач | Динамическое программирование |

## 1. Два указателя — [0:40](https://www.youtube.com/watch?v=cpuRbnWEPio&t=40s)

### 1.1. Указатели с двух сторон

**Гринфлаги:** отсортированный массив; палиндром; ответ получается при сужении диапазона.

Пример из видео: в отсортированном массиве найти два числа с суммой `target`.

Инвариант: если текущая сумма мала, левый элемент уже не поможет — увеличиваем `l`; если велика — уменьшаем `r`.

```go
func twoSumSorted(a []int, target int) (int, int) {
	l, r := 0, len(a)-1
	for l < r {
		sum := a[l] + a[r]
		switch {
		case sum == target:
			return l, r
		case sum < target:
			l++
		default:
			r--
		}
	}
	return -1, -1
}
```

Сложность: `O(n)` по времени, `O(1)` дополнительной памяти.

> В автосубтитрах около 1:15 направления указателей перепутаны. Для возрастающего массива правило именно такое: `sum < target → l++`, `sum > target → r--`.

### 1.2. По указателю на каждую последовательность

**Гринфлаги:** два отсортированных массива/строки; объединение, пересечение или разность.

```go
func intersectSorted(a, b []int) []int {
	i, j := 0, 0
	ans := make([]int, 0)
	for i < len(a) && j < len(b) {
		switch {
		case a[i] < b[j]:
			i++
		case a[i] > b[j]:
			j++
		default:
			ans = append(ans, a[i])
			i++
			j++
		}
	}
	return ans
}
```

Сложность: `O(n+m)`. Память результата не следует смешивать с дополнительной памятью алгоритма.

### 1.3. Быстрый и медленный

**Гринфлаг:** изменить исходный массив `in-place`, обычно сохранив относительный порядок.

Смысл: `fast` читает, `slow` показывает, куда писать следующий подходящий элемент.

```go
func moveZeroes(a []int) {
	slow := 0
	for fast := 0; fast < len(a); fast++ {
		if a[fast] != 0 {
			a[slow], a[fast] = a[fast], a[slow]
			slow++
		}
	}
}
```

Ключевой вопрос: **при каком условии двигается `slow`?** `fast` обычно идёт всегда.

## 2. Скользящее окно — [8:34](https://www.youtube.com/watch?v=cpuRbnWEPio&t=514s)

### 2.1. Окно фиксированной длины

**Гринфлаги:** «`k` подряд идущих», «подмассив длины `k`», локальный агрегат фиксированного размера.

```go
func maxWindowSum(a []int, k int) (int, bool) {
	if k <= 0 || k > len(a) {
		return 0, false
	}
	sum := 0
	for i := 0; i < k; i++ {
		sum += a[i]
	}
	best := sum
	for r := k; r < len(a); r++ {
		sum += a[r] - a[r-k]
		best = max(best, sum)
	}
	return best, true
}
```

Сложность: `O(n)` вместо пересчёта каждого окна за `O(k)`.

### 2.2. Непересекающиеся окна

**Гринфлаги:** последовательность нужно разбить на идущие подряд группы; каждый элемент принадлежит ровно одной группе.

Примеры: сжать серии одинаковых символов; превратить отсортированные числа в диапазоны.

Каркас:

```go
for l := 0; l < len(a); {
	r := l
	for r+1 < len(a) && belongsToSameGroup(a[r], a[r+1]) {
		r++
	}
	consumeGroup(a[l : r+1])
	l = r + 1
}
```

### 2.3. Пересекающиеся окна переменной длины

**Гринфлаги:** самый длинный/короткий непрерывный фрагмент, удовлетворяющий ограничению; окно можно расширять и сжимать.

Пример из видео: максимальная серия единиц, если разрешено заменить не более `k` нулей.

```go
func longestOnes(a []int, k int) int {
	l, zeros, best := 0, 0, 0
	for r, x := range a {
		if x == 0 {
			zeros++
		}
		for zeros > k {
			if a[l] == 0 {
				zeros--
			}
			l++
		}
		best = max(best, r-l+1)
	}
	return best
}
```

Инвариант: после внутреннего цикла окно `[l, r]` снова валидно. Каждый указатель проходит массив не более одного раза → `O(n)`.

Окно работает не всегда: если нет монотонного способа восстановить валидность при движении `l`, подумай о префиксах, `map`, бинарном поиске или DP.

## 3. Хеш-таблицы — [16:22](https://www.youtube.com/watch?v=cpuRbnWEPio&t=982s)

В Go:

- множество: `map[T]struct{}`;
- счётчик: `map[T]int`;
- соответствие: `map[K]V`;
- проверка существования: `v, ok := m[key]`.

### 3.1. Техника подсчёта

**Гринфлаги:** частоты, анаграмма, одинаковое число вхождений.

```go
func isAnagram(a, b string) bool {
	if len(a) != len(b) { // корректно для ASCII/байтовых задач
		return false
	}
	count := make(map[byte]int)
	for i := range a {
		count[a[i]]++
		count[b[i]]--
	}
	for _, n := range count {
		if n != 0 {
			return false
		}
	}
	return true
}
```

Для Unicode используй `[]rune`, а не индексацию строки по байтам.

### 3.2. Key→Value→Key (bucket по частоте)

**Гринфлаги:** сортировка по частоте, top-k по частоте.

1. `value → count`.
2. Инверсия: `count → []value`.
3. Обход частот с конца.

```go
func topKFrequent(nums []int, k int) []int {
	count := make(map[int]int)
	for _, x := range nums {
		count[x]++
	}
	buckets := make([][]int, len(nums)+1)
	for x, f := range count {
		buckets[f] = append(buckets[f], x)
	}
	ans := make([]int, 0, k)
	for f := len(buckets)-1; f >= 0 && len(ans) < k; f-- {
		for _, x := range buckets[f] {
			ans = append(ans, x)
			if len(ans) == k {
				break
			}
		}
	}
	return ans
}
```

Сложность: `O(n)` времени и `O(n)` памяти. Вложенный цикл не делает решение квадратичным: суммарно во всех бакетах не более `n` элементов.

### 3.3. Выбор смысла ключа

Если задача не про частоты, спроси:

- что нужно узнавать за `O(1)`;
- что однозначно описывает уже обработанное состояние;
- может ли ключом быть значение, остаток, префиксная сумма, нормализованная строка или координата.

## 4. Точки и отрезки — [21:04](https://www.youtube.com/watch?v=cpuRbnWEPio&t=1264s)

Для двух замкнутых интервалов `[a,b]` и `[c,d]`:

- пересечение существует, если `max(a,c) <= min(b,d)`;
- пересечение: `[max(a,c), min(b,d)]`;
- объединение пересекающихся: `[min(a,c), max(b,d)]`.

### 4.1. Один список интервалов: сортировка и слияние

```go
import "sort"

type Interval struct{ Start, End int }

func mergeIntervals(xs []Interval) []Interval {
	if len(xs) == 0 {
		return nil
	}
	sort.Slice(xs, func(i, j int) bool {
		if xs[i].Start == xs[j].Start {
			return xs[i].End < xs[j].End
		}
		return xs[i].Start < xs[j].Start
	})
	ans := []Interval{xs[0]}
	for _, cur := range xs[1:] {
		last := &ans[len(ans)-1]
		if cur.Start <= last.End {
			last.End = max(last.End, cur.End)
		} else {
			ans = append(ans, cur)
		}
	}
	return ans
}
```

Сложность: `O(n log n)` из-за сортировки.

### 4.2. Два списка интервалов

Сравниваем текущую пару, добавляем пересечение и двигаем интервал, который закончился раньше. Сложность `O(n+m)`.

### 4.3. Метод точек / sweep line

**Гринфлаги:** максимум одновременных событий, минимальное число комнат/платформ, состояние «в конкретный момент».

Каждый интервал превращается в события `(start,+1)` и `(end,-1)`. Важна политика равных координат: если ресурс можно переиспользовать в момент окончания, событие `-1` сортируется раньше `+1`.

```go
type Event struct{ X, Delta int }

func minRooms(xs []Interval) int {
	events := make([]Event, 0, 2*len(xs))
	for _, in := range xs {
		events = append(events, Event{in.Start, 1}, Event{in.End, -1})
	}
	sort.Slice(events, func(i, j int) bool {
		if events[i].X == events[j].X {
			return events[i].Delta < events[j].Delta
		}
		return events[i].X < events[j].X
	})
	cur, best := 0, 0
	for _, e := range events {
		cur += e.Delta
		best = max(best, cur)
	}
	return best
}
```

## 5. Бинарный поиск — [29:23](https://www.youtube.com/watch?v=cpuRbnWEPio&t=1763s)

Главная идея — искать не обязательно число, а **первую позицию, где монотонный предикат `good(i)` становится истинным**.

```go
// Возвращает первый i из [0,n), для которого good(i) == true; иначе n.
func lowerBound(n int, good func(int) bool) int {
	l, r := 0, n
	for l < r {
		m := l + (r-l)/2
		if good(m) {
			r = m
		} else {
			l = m + 1
		}
	}
	return l
}
```

Пример — диапазон вхождений `target`:

```go
func equalRange(a []int, target int) (int, int) {
	left := lowerBound(len(a), func(i int) bool { return a[i] >= target })
	right := lowerBound(len(a), func(i int) bool { return a[i] > target })
	if left == len(a) || a[left] != target {
		return -1, -1
	}
	return left, right - 1
}
```

**Двойной бинарный поиск:** два поиска границ или предварительный поиск участка, после которого выполняется обычный поиск. Пример из видео — поиск в циклически сдвинутом отсортированном массиве.

Чек-лист против ошибок:

- заранее выбери полуинтервал `[l,r)` или закрытый `[l,r]` и не смешивай;
- середина: `l + (r-l)/2`;
- докажи монотонность `good`;
- проверь «ничего не найдено», первый и последний элементы, дубликаты.

## 6. Стек — [34:36](https://www.youtube.com/watch?v=cpuRbnWEPio&t=2076s)

В Go стек обычно реализуется слайсом:

```go
stack := make([]int, 0)
stack = append(stack, x)          // push
x = stack[len(stack)-1]           // top
stack = stack[:len(stack)-1]      // pop
```

### 6.1. Стек промежуточных результатов

**Гринфлаги:** нужно отложить незавершённую операцию и вернуться к ней; скобки; вычисление выражений.

Примеры из видео: валидные скобки, обратная польская запись.

### 6.2. Монотонный стек

**Гринфлаги:** ближайший больший/меньший элемент слева/справа, следующий более тёплый день.

```go
func nextGreater(a []int) []int {
	ans := make([]int, len(a))
	for i := range ans {
		ans[i] = -1
	}
	stack := make([]int, 0) // индексы; значения убывают
	for i, x := range a {
		for len(stack) > 0 && a[stack[len(stack)-1]] < x {
			j := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			ans[j] = x
		}
		stack = append(stack, i)
	}
	return ans
}
```

Почему `O(n)`: каждый индекс кладётся в стек и извлекается не более одного раза.

### 6.3. Псевдостек

Если задача выглядит стековой, но нужны не сами сохранённые значения, а только размер/баланс/числовой параметр, стек можно заменить счётчиком.

```go
func validParenthesesOneType(s string) bool {
	balance := 0
	for _, ch := range s {
		if ch == '(' {
			balance++
		} else if ch == ')' {
			balance--
			if balance < 0 {
				return false
			}
		}
	}
	return balance == 0
}
```

## 7. Префиксные значения — [43:11](https://www.youtube.com/watch?v=cpuRbnWEPio&t=2591s)

Классический префиксный массив строится длины `n+1`:

```go
func prefixSums(a []int) []int {
	p := make([]int, len(a)+1)
	for i, x := range a {
		p[i+1] = p[i] + x
	}
	return p
}

// Сумма a[l:r], правая граница не включена.
func rangeSum(p []int, l, r int) int { return p[r] - p[l] }
```

### 7.1. Массивы агрегатов

**Гринфлаги:** надо быстро знать суммы/произведения/XOR по строкам, столбцам, диагоналям или диапазонам; запросов много.

Цена: предподсчёт `O(n)`, затем запрос `O(1)`.

### 7.2. Бегущий префикс

Если нужны только текущие левый и правый агрегаты, массив можно заменить переменными.

Пример из видео — pivot index:

```go
func pivotIndex(a []int) int {
	total := 0
	for _, x := range a {
		total += x
	}
	left := 0
	for i, x := range a {
		right := total - left - x
		if left == right {
			return i
		}
		left += x
	}
	return -1
}
```

Связка, которую часто стоит проверять: **префиксная сумма как ключ `map`**. Например, число подмассивов с суммой `k` ищется по ранее встреченным значениям `prefix-k`.

## 8. Односвязный список — [49:24](https://www.youtube.com/watch?v=cpuRbnWEPio&t=2964s)

```go
type ListNode struct {
	Val  int
	Next *ListNode
}
```

База, которую надо уметь написать без раздумий: найти середину (`slow/fast`), развернуть список, слить два списка.

```go
func reverse(head *ListNode) *ListNode {
	var prev *ListNode
	for head != nil {
		next := head.Next
		head.Next = prev
		prev = head
		head = next
	}
	return prev
}
```

### 8.1. Фиктивный (dummy) узел

**Гринфлаги:** строится новый порядок из существующих узлов; удаление может затронуть голову; хочется убрать особый случай для первого элемента.

```go
func mergeLists(a, b *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	for a != nil && b != nil {
		if a.Val <= b.Val {
			tail.Next, a = a, a.Next
		} else {
			tail.Next, b = b, b.Next
		}
		tail = tail.Next
	}
	if a != nil { tail.Next = a } else { tail.Next = b }
	return dummy.Next
}
```

В Go dummy-узел не нужно освобождать вручную: недостижимую память обработает GC.

### 8.2. Частичный разворот

**Гринфлаг:** для списка хочется применить движение с двух сторон, но назад идти нельзя.

Рецепт для палиндрома/reorder list:

1. Найти середину быстрым и медленным указателями.
2. Развернуть вторую половину.
3. Применить два указателя к половинам.
4. Если контракт требует — восстановить список.

## 9. Перебор комбинаций — [59:42](https://www.youtube.com/watch?v=cpuRbnWEPio&t=3582s)

### 9.1. Полный перебор

**Гринфлаги:** нужны все комбинации, перестановки или подмножества; допустимы все варианты.

Помни: экспоненциальная сложность может быть оптимальной относительно размера ответа. Нельзя вывести `2^n` подмножеств быстрее `Ω(2^n)`.

### 9.2. Backtracking

**Гринфлаги:** нужны не все варианты, а только допустимые; частичное решение можно рано отсечь.

Шаблон Go:

```go
func generateParenthesis(n int) []string {
	ans := make([]string, 0)
	buf := make([]byte, 0, 2*n)
	var dfs func(open, close int)
	dfs = func(open, close int) {
		if len(buf) == 2*n {
			ans = append(ans, string(buf)) // string делает копию данных
			return
		}
		if open < n {
			buf = append(buf, '(')
			dfs(open+1, close)
			buf = buf[:len(buf)-1] // undo
		}
		if close < open {
			buf = append(buf, ')')
			dfs(open, close+1)
			buf = buf[:len(buf)-1] // undo
		}
	}
	dfs(0, 0)
	return ans
}
```

Модель: **выбор → рекурсивный спуск → отмена выбора**. Отсечение (`close < open`) — главная разница с тупым перебором всех строк.

Go-ловушка: когда сохраняешь текущий `[]int`, копируй его:

```go
ans = append(ans, append([]int(nil), path...))
```

Иначе все ответы могут ссылаться на один backing array.

## 10. Деревья — [1:07:16](https://www.youtube.com/watch?v=cpuRbnWEPio&t=4036s)

```go
type TreeNode struct {
	Val         int
	Left, Right *TreeNode
}
```

Почти всегда первая строка рекурсивной функции — обработка `nil`.

### 10.1. Снизу вверх (postorder)

**Гринфлаги:** родителю нужен результат детей; высота, баланс, диаметр.

```go
func diameter(root *TreeNode) int {
	best := 0
	var height func(*TreeNode) int
	height = func(node *TreeNode) int {
		if node == nil {
			return 0
		}
		left := height(node.Left)
		right := height(node.Right)
		best = max(best, left+right)
		return 1 + max(left, right)
	}
	height(root)
	return best
}
```

Важно разделять:

- что функция **возвращает родителю** (`height`);
- что обновляет как **глобальный ответ** (`best`).

Сложность: `O(n)` времени, `O(h)` стека, где `h` — высота дерева.

### 10.2. Сверху вниз (preorder)

**Гринфлаги:** накопление по пути от корня; сумма, максимум, границы, глубина.

```go
func hasPathSum(root *TreeNode, target int) bool {
	if root == nil {
		return false
	}
	remaining := target - root.Val
	if root.Left == nil && root.Right == nil {
		return remaining == 0
	}
	return hasPathSum(root.Left, remaining) ||
		hasPathSum(root.Right, remaining)
}
```

Некоторые задачи совмещают оба направления: вниз передаётся состояние пути, вверх возвращается агрегат поддерева.

## 11. Графы — [1:17:38](https://www.youtube.com/watch?v=cpuRbnWEPio&t=4658s)

Представления в Go:

```go
adj := make([][]int, n)       // вершины 0..n-1
visited := make([]bool, n)
```

Для матрицы не обязательно строить список смежности: соседей можно генерировать четырьмя направлениями.

### 11.1. BFS и DFS

Оба обхода имеют `O(V+E)` времени для списка смежности: каждая вершина посещается один раз, каждое ребро просматривается один раз в ориентированном графе и дважды в неориентированном. Дополнительная память — `O(V)`.

- **BFS** — очередь; идёт слоями; выбирай для минимума рёбер/шагов в невзвешенном графе.
- **DFS** — рекурсия или стек; удобен для полного обхода, компонент и возвратных вычислений.

#### Как решать через BFS

1. Определи, что является вершиной, а что — переходом между вершинами.
2. Создай очередь и структуру `visited` либо `dist`.
3. Пометь старт **до добавления в очередь**, чтобы одна вершина не попала туда несколько раз.
4. Доставай вершины с начала очереди и добавляй ещё не посещённых соседей в конец.
5. Если нужен кратчайший путь, храни расстояние и при необходимости родителя каждой вершины.

Инвариант BFS: когда вершина извлечена из очереди, кратчайшее расстояние до неё в невзвешенном графе уже найдено. Очередь обрабатывает вершины по слоям: сначала расстояние `0`, затем `1`, `2` и так далее.

Пример — [LeetCode 1971. Find if Path Exists in Graph](https://leetcode.com/problems/find-if-path-exists-in-graph/). Дан неориентированный граф, начальная вершина `source` и конечная `destination`. Нужно проверить, существует ли между ними путь.

```go
func validPath(n int, edges [][]int, source int, destination int) bool {
	graph := make(map[int][]int)

	// Строим неориентированный граф.
	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	queue := []int{source}
	visited := make(map[int]bool)
	visited[source] = true

	for len(queue) > 0 {
		// Берём первую вершину из очереди.
		top := queue[0]
		queue = queue[1:]

		if top == destination {
			return true
		}

		for _, to := range graph[top] {
			if !visited[to] {
				visited[to] = true
				queue = append(queue, to)
			}
		}
	}

	return false
}
```

Как движется BFS:

```text
source → queue → достаём вершину → смотрим соседей
       → добавляем непосещённых в queue → повторяем
```

Вершина помечается посещённой **при добавлении в очередь**, иначе разные соседи могут добавить её повторно. Проверка `top == destination` позволяет завершить обход сразу после достижения цели.

#### Как решать через DFS

1. Определи вершины и соседей так же, как для BFS.
2. При входе в вершину сразу пометь её посещённой.
3. Для каждого непосещённого соседа продолжи обход в глубину.
4. После возврата из соседей обработай результат, если задача собирает ответ снизу вверх.

Инвариант DFS: текущий стек вызовов или явный стек содержит путь, по которому алгоритм углубился из старта. `visited` не позволяет зациклиться и повторно обрабатывать вершины.

Та же задача 1971 через рекурсивный DFS:

```go
func validPath(n int, edges [][]int, source int, destination int) bool {
	graph := make(map[int][]int)

	// Строим неориентированный граф.
	for _, edge := range edges {
		u := edge[0]
		v := edge[1]

		graph[u] = append(graph[u], v)
		graph[v] = append(graph[v], u)
	}

	visited := make(map[int]bool)

	var dfs func(int) bool
	dfs = func(v int) bool {
		if v == destination {
			return true
		}

		visited[v] = true

		for _, to := range graph[v] {
			if !visited[to] && dfs(to) {
				return true
			}
		}

		return false
	}

	return dfs(source)
}
```

Как движется DFS:

```text
source → dfs(source) → dfs(сосед) → ещё глубже
       → destination найден? → true поднимается по стеку вызовов
```

Здесь `dfs(v)` означает: **можно ли добраться из вершины `v` до `destination`**. Если вложенный вызов вернул `true`, результат сразу передаётся наверх. Для глубокой цепочки рекурсивный DFS можно заменить явным стеком.

В обоих решениях построение `graph` и использование `visited` практически одинаковы. Меняется структура управления обходом: очередь у BFS и стек вызовов у DFS.

Сложность обоих решений:

- время — `O(V + E)`;
- весь объём памяти вместе со списком смежности — `O(V + E)`;
- дополнительная память обхода без учёта графа — `O(V)`.

#### Как выбрать между BFS и DFS

| Задача | Предпочтительный обход | Почему |
|---|---|---|
| Минимальное число шагов в невзвешенном графе | BFS | Первый найденный слой даёт минимум |
| Найти любой путь или проверить достижимость | BFS или DFS | Оба полностью обходят достижимую часть |
| Посчитать компоненты, острова или размер области | BFS или DFS | Один запуск покрывает одну компоненту |
| Проверить цикл в ориентированном графе | DFS с цветами или топологическая сортировка | Нужно различать текущий путь и завершённые вершины |
| Собрать результат после обработки потомков | Рекурсивный DFS | Удобна обработка после рекурсивных вызовов |
| Граф может быть очень глубоким | BFS или итеративный DFS | Нет риска слишком глубокой рекурсии |

Важно: порядок обхода соседей влияет на конкретный порядок вершин в результате, но не на достижимость. Если тест ожидает определённый порядок, отсортируй списки смежности или соблюдай заданный порядок рёбер.

### 11.2. Кратчайший путь

**Гринфлаги:** минимальное число шагов, ходов или единиц времени; все рёбра равной стоимости.

Чтобы восстановить маршрут, кроме `dist` храни `parent[to] = v`, затем иди от цели назад.

Если веса различаются:

- неотрицательные веса → Dijkstra;
- веса только `0/1` → 0–1 BFS;
- отрицательные веса → Bellman–Ford или другой подход по ограничениям.

### 11.3. Компоненты связности

**Гринфлаги:** острова, области, группы, максимальный размер компоненты.

Внешний цикл ищет ещё не посещённую вершину; каждый новый DFS/BFS означает новую компоненту.

Пример через DFS:

```go
func countComponents(adj [][]int) int {
	visited := make([]bool, len(adj))

	var dfs func(int)
	dfs = func(v int) {
		visited[v] = true
		for _, to := range adj[v] {
			if !visited[to] {
				dfs(to)
			}
		}
	}

	components := 0
	for v := range adj {
		if visited[v] {
			continue
		}
		components++
		dfs(v)
	}
	return components
}
```

Чтобы решить ту же задачу через BFS, тело `dfs(v)` заменяется очередью, начинающейся с `v`. Внешний цикл и смысл счётчика остаются теми же. Это полезный приём: сначала выдели **логику одного обхода**, затем оберни её внешним циклом по всем вершинам.

### 11.4. Порядок зависимостей

**Гринфлаги:** prerequisite, порядок задач/курсов, проверка цикла в ориентированном графе.

Алгоритм Кана:

1. Посчитать `indegree` каждой вершины.
2. Положить в очередь вершины с `indegree == 0`.
3. Извлекать вершину, уменьшать степени её соседей.
4. Если обработано меньше `n` вершин — есть цикл.

```go
func topoSort(n int, edges [][2]int) ([]int, bool) {
	adj := make([][]int, n)
	indegree := make([]int, n)
	for _, e := range edges {
		from, to := e[0], e[1]
		adj[from] = append(adj[from], to)
		indegree[to]++
	}
	q := make([]int, 0, n)
	for v, d := range indegree {
		if d == 0 { q = append(q, v) }
	}
	order := make([]int, 0, n)
	for head := 0; head < len(q); head++ {
		v := q[head]
		order = append(order, v)
		for _, to := range adj[v] {
			indegree[to]--
			if indegree[to] == 0 { q = append(q, to) }
		}
	}
	return order, len(order) == n
}
```

## 12. Динамическое программирование — [1:34:14](https://www.youtube.com/watch?v=cpuRbnWEPio&t=5654s)

DP применимо, когда есть:

1. Повторяющиеся подзадачи.
2. Состояние, достаточное для продолжения решения.
3. Переход из меньших состояний.
4. Базовые случаи и порядок вычисления.

Перед кодом проговори фразу: **`dp[...]` означает ...**. Если смысл состояния сформулировать нельзя, код почти наверняка будет путаным.

### 12.1. Одномерное DP

Пример из видео — число способов подняться на `n` ступеней шагами 1 или 2:

```go
func climbStairs(n int) int {
	if n <= 1 { return 1 }
	prev2, prev1 := 1, 1
	for step := 2; step <= n; step++ {
		prev2, prev1 = prev1, prev1+prev2
	}
	return prev1
}
```

Состояние: `dp[i]` — число способов попасть на ступень `i`. Переход: `dp[i] = dp[i-1] + dp[i-2]`.

Оптимизация памяти до `O(1)` допустима, только если будущему нужны несколько последних состояний. Сначала напиши понятный DP-массив, затем оптимизируй.

Другой маркер одномерного DP — «максимальная сумма без соседних элементов» (`House Robber`).

### 12.2. Многомерное DP

**Гринфлаги:** состояние определяется двумя и более независимыми параметрами: позициями в двух строках, координатами, индексом и остатком ёмкости.

Общий шаблон:

```go
dp := make([][]int, n+1)
for i := range dp {
	dp[i] = make([]int, m+1)
}
// 1) базовые строки/столбцы
// 2) порядок обхода, при котором зависимости уже посчитаны
// 3) dp[i][j] = transition(...)
```

Пример класса задач: 0/1 knapsack, LCS, edit distance, число путей по сетке.

Главная сложность DP — не размер таблицы, а выбор смысла состояния и перехода. Полезные вопросы:

- Какие решения меньшего размера уже помогли бы решить текущую задачу?
- Что минимально нужно знать о прошлом?
- Какие варианты последнего действия существуют?
- В каком порядке состояния становятся известны?

## 13. Базовые алгоритмы сортировки

Эти сортировки полезны для понимания инвариантов, вложенных циклов и оценки сложности. Все примеры меняют переданный слайс `[]int` **на месте**.

| Алгоритм | Идея | Лучший случай | Средний / худший | Память | Стабильный |
|---|---|---:|---:|---:|---|
| Bubble Sort | Менять соседние элементы | `O(n)`* | `O(n²)` | `O(1)` | Да |
| Selection Sort | Находить минимум в хвосте | `O(n²)` | `O(n²)` | `O(1)` | Обычно нет |
| Insertion Sort | Вставлять элемент в отсортированную часть | `O(n)` | `O(n²)` | `O(1)` | Да |

`*` Только в оптимизированном Bubble Sort: если за проход обменов не было, массив уже отсортирован.

**Стабильная сортировка** сохраняет порядок равных элементов. Это важно при сортировке структур по одному полю, когда порядок по другому полю нужно сохранить.

### 13.1. Bubble Sort — пузырьковая сортировка

Сравниваем соседей и меняем их местами, если они стоят неверно. После каждого прохода самый большой элемент неотсортированной части оказывается справа.

```text
[5, 2, 4] → [2, 5, 4] → [2, 4, 5]
                         ↑
                  максимум на месте
```

Инвариант: после прохода с `end` элемент `nums[end]` уже находится на окончательной позиции.

```go
func bubbleSort(nums []int) {
	for end := len(nums) - 1; end > 0; end-- {
		swapped := false

		for i := 0; i < end; i++ {
			if nums[i] > nums[i+1] {
				nums[i], nums[i+1] = nums[i+1], nums[i]
				swapped = true
			}
		}

		if !swapped {
			return
		}
	}
}
```

### 13.2. Selection Sort — сортировка выбором

Делим массив на отсортированный префикс и неотсортированный хвост. На каждом шаге находим минимум в хвосте и ставим его в начало хвоста.

```text
[]     | [5, 2, 4, 1] → минимум 1 → [1]    | [2, 4, 5]
[1]    | [2, 4, 5]    → минимум 2 → [1, 2] | [4, 5]
```

Инвариант: перед итерацией `i` часть `nums[:i]` уже отсортирована и содержит `i` наименьших элементов.

```go
func selectionSort(nums []int) {
	for i := 0; i < len(nums)-1; i++ {
		minIndex := i

		for j := i + 1; j < len(nums); j++ {
			if nums[j] < nums[minIndex] {
				minIndex = j
			}
		}

		if minIndex != i {
			nums[i], nums[minIndex] = nums[minIndex], nums[i]
		}
	}
}
```

Здесь мало обменов — максимум `n-1`, но сравнений всё равно `O(n²)`, даже если массив уже отсортирован. Обычная реализация не стабильна: далёкий минимальный элемент при обмене может перепрыгнуть через равный ему.

### 13.3. Insertion Sort — сортировка вставками

Берём следующий элемент и вставляем его в правильную позицию уже отсортированного префикса. Похоже на раскладку карт в руке.

```text
[5] | [2, 4]
вставляем 2: [2, 5] | [4]
вставляем 4: [2, 4, 5]
```

Инвариант: перед обработкой `nums[i]` часть `nums[:i]` уже отсортирована.

```go
func insertionSort(nums []int) {
	for i := 1; i < len(nums); i++ {
		current := nums[i]
		j := i - 1

		for j >= 0 && nums[j] > current {
			nums[j+1] = nums[j]
			j--
		}

		nums[j+1] = current
	}
}
```

Особенно полезна для почти отсортированных данных: тогда сдвигов мало и время близко к `O(n)`. Строгое условие `nums[j] > current` сохраняет порядок равных элементов.

### Шпаргалка

```text
Соседние пары + обмен         → Bubble Sort
Поиск минимума в хвосте       → Selection Sort
Сдвиг вправо + вставка        → Insertion Sort
Почти отсортированный массив  → Insertion Sort
Большой массив в Go           → sort.Ints / пакет slices, а не O(n²)-сортировки
```

## Go: практические ловушки на алгоритмическом собеседовании

### Строки

- `len(s)` — число байтов, не Unicode-символов.
- `s[i]` — `byte`.
- Для Unicode: `r := []rune(s)`.
- Конкатенация строк в большом цикле может быть квадратичной; используй `strings.Builder` или `[]byte`.

### Слайсы

- `append` может переаллоцировать backing array.
- Сохраняя текущий путь backtracking, делай копию.
- `make([]int, n)` создаёт длину `n`; `make([]int, 0, n)` — пустой слайс с capacity `n`.
- Очередь через индекс `head` обычно проще и быстрее `container/list`.

### Map

- Чтение отсутствующего ключа возвращает zero value; когда это важно, проверяй `ok`.
- Порядок обхода `map` не гарантирован.
- `delete(m, key)` безопасен и для отсутствующего ключа.

### Числа

- Для сумм и произведений по большим ограничениям может понадобиться `int64`.
- Не угадывай по привычке: оцени максимум из ограничений.

### Рекурсия

- Для глубокого линейного графа итеративный DFS безопаснее рекурсивного.
- В деревьях рекурсия обычно естественна, но всё равно оцени высоту `h`.

## Что проговаривать во время решения

Хороший короткий сценарий:

1. «Наивно можно сделать ..., это займёт `O(...)`.»
2. «В условии есть маркер ...; поэтому проверю паттерн ...»
3. «Инвариант такой: ...»
4. «Каждый элемент входит/выходит не более одного раза, поэтому время `O(n)`.»
5. «Дополнительная память `O(...)`; результат считаю/не считаю частью auxiliary space.»
6. «Проверю пустой ввод, один элемент, дубликаты и граничное значение.»

## Как тренироваться

Не решай длинный случайный список задач. Делай блоками по паттерну:

1. Разбери один эталонный пример.
2. Закрой решение и воспроизведи общий шаблон.
3. Реши 3–5 вариаций, каждый раз выпиши гринфлаг и инвариант.
4. Через несколько дней реши одну задачу без тега темы.
5. Веди журнал ошибок: неверный паттерн, неверный инвариант, границы, сложность, особенности Go.

Минимальный порядок подготовки:

1. Два указателя, окно, `map`.
2. Интервалы, бинарный поиск, стек, префиксы.
3. Связные списки и backtracking.
4. Деревья, графы, DP.

Главный критерий прогресса: по новому условию ты умеешь назвать 1–2 вероятных паттерна и быстро объяснить, почему они подходят или не подходят.
