# Пакет `sync` и `atomic`

Пакет `sync` — про **синхронизацию доступа к общей памяти**, когда несколько горутин трогают одни и те же данные. Документация прямо говорит: высокоуровневую координацию чаще делают каналами, а `Mutex` / `WaitGroup` — базовые примитивы, особенно когда нужна защита структуры или ожидание группы задач.

Без синхронизации возникает **data race**: две горутины одновременно читают/пишут одну переменную → результат непредсказуем. Ловят это через `go test -race` / `go run -race`.

---

## `sync.WaitGroup` — дождаться группы горутин

`WaitGroup` — примитив для ожидания, пока множество горутин завершат работу. Это надёжная замена `time.Sleep()`: ждёте ровно до конца работы, а не «надеетесь», что sleep хватит.

Счётчик задач: `Add` перед стартом, `Done` в конце каждой, `Wait` блокируется, пока счётчик не станет `0`.

```go
package main

import (
    "fmt"
    "sync"
    "time"
)

func main() {
    wg := sync.WaitGroup{}

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func(i int) {
            defer wg.Done()
            time.Sleep(time.Duration(i) * time.Second)
            fmt.Println("Горутина", i, "завершила свое выполнение")
        }(i)
    }

    wg.Wait()
    fmt.Println("Все горутины завершили свое выполнение!")
}
```

[Go Playground](https://go.dev/play/p/XdsoK-FSPR_m)

Перед стартом каждой горутины `wg.Add(1)` увеличивает счётчик. Внутри горутины `wg.Done()` (это `Add(-1)`) уменьшает его. В `main` `wg.Wait()` ждёт, пока счётчик не станет нулём.

**Важно:** `Add` вызывай **до** `go`, иначе `Wait` может завершиться раньше времени. В новых версиях Go у `WaitGroup` есть удобный `Go(f)` — сам делает `Add` / `Done` вокруг функции.

## `sync.Mutex` — взаимное исключение

`Mutex` (mutual exclusion) — примитив, который пускает в **критическую секцию** только одну горутину за раз. Методы: `Lock()` и `Unlock()`.

```go
package main

import (
    "fmt"
    "sync"
)

func main() {
    var (
        counter int
        lock    sync.Mutex
    )

    wg := &sync.WaitGroup{}

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()

            lock.Lock()
            counter++
            fmt.Println("Счетчик:", counter)
            lock.Unlock()
        }()
    }

    wg.Wait()
    fmt.Println("Итоговый счетчик:", counter)
}
```

[Go Playground](https://go.dev/play/p/eDm4HHbAGEB)

Перед обновлением счётчика вызываем `lock.Lock()` — другие горутины не зайдут в эту секцию. После обновления — `lock.Unlock()`.

Идиома: сразу после `Lock()` ставь `defer Unlock()` — иначе при `return` / panic легко получить deadlock:

```go
func inc() {
    mu.Lock()
    defer mu.Unlock()
    counter++
}
```

Zero value мьютекса — разблокированный. Копировать `Mutex` после использования нельзя (обычно держат в struct по указателю / не копируют struct с мьютексом).

## `sync.RWMutex` — много читателей

`RWMutex` разделяет роли:

- `RLock` / `RUnlock` — много читателей параллельно;
- `Lock` / `Unlock` — один писатель, читателей в это время нет.

Имеет смысл, когда чтений сильно больше записей. Если записи частые — обычный `Mutex` часто проще и не хуже.

---

## `sync.Once` — ровно один раз

```go
var once sync.Once

once.Do(func() {
    // инициализация: выполнится только один раз
})
```

Даже если `Do` вызовут из многих горутин — тело побежит один раз. Типично для lazy init.

---

## Коротко про остальное в `sync`

- **`sync.Map`** — concurrent map для узких кейсов (редко пишут, много читают / ключи у разных горутин разные). Для обычной map чаще достаточно `map` + мьютекс.
- **`sync.Pool`** — переиспользование временных объектов (снижение аллокаций), не для «важных» долгоживущих данных.
- **`sync.Cond`** — ждать условия вместе с мьютексом; на собесе реже, чем Mutex/WaitGroup.

## Пакет `sync/atomic` — атомарные операции

**Атомарная операция** — действие, которое выполняется **целиком и сразу** с точки зрения других горутин. Нельзя «увидеть середину»: либо ещё не началось, либо уже полностью закончилось. Это read-modify-write без мьютекса (обычно на уровне CPU-инструкций).

Обычный `counter++` — не атом: прочитал → прибавил → записал. Две горутины могут потерять обновление. `atomic.Add` делает это неделимо.

Работает для простых типов: числа, указатели, `atomic.Value` / `atomic.Pointer`.

```go
package main

import (
    "fmt"
    "sync"
    "sync/atomic"
)

func main() {
    var counter int64
    wg := &sync.WaitGroup{}

    for i := 0; i < 5; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            atomic.AddInt64(&counter, 1)
            fmt.Println("Счетчик:", atomic.LoadInt64(&counter))
        }()
    }

    wg.Wait()
    fmt.Println("Итоговый счетчик:", counter)
}
```

[Go Playground](https://go.dev/play/p/cLvSy7Mccdj)

`AddInt64` атомарно увеличивает счётчик, `LoadInt64` атомарно читает. Мьютекс здесь не нужен.

В современном Go удобнее типы-обёртки:

```go
var counter atomic.Int64
counter.Add(1)
fmt.Println(counter.Load())
```

Ещё важен **CompareAndSwap (CAS)**: «если ещё было X — запиши Y». На этом строят lock-free флаги и простые state machine.

**Ограничение:** атомик защищает **одну** операцию. Если нужно обновить два поля согласованно или сделать «прочитал → проверил → записал» из нескольких шагов — нужен `Mutex` (или канал с одним владельцем данных).

## Когда что выбирать

| Задача                                  | Инструмент          |
| --------------------------------------- | ------------------- |
| Дождаться N горутин                     | `WaitGroup`         |
| Защитить map / struct / несколько полей | `Mutex` / `RWMutex` |
| Простой счётчик / флаг                  | `atomic`            |
| Передать данные / пайплайн / владение   | канал               |
| Инициализация один раз                  | `Once`              |

Правило для собеса: каналы — когда моделируешь поток сообщений; мьютекс — когда несколько горутин делят структуру; атомик — узкий hot path на одном числе/флаге. Не тащи атомики в сложную логику «ради скорости» — легко ошибиться.

---

## Фраза на 20 секунд

`sync` даёт `Mutex` / `RWMutex` для критических секций, `WaitGroup` для ожидания горутин, `Once` для одноразовой init. `atomic` — lock-free операции над простыми значениями. Data race ловят `-race`. Сложное состояние — под мьютекс или одному владельцу через канал; простой счётчик — atomic.
