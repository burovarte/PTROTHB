# Ошибки и их обработка

В Go ошибка — обычное **значение**, а не исключение вроде `try/catch`. Тип `error` — встроенный интерфейс с одним методом:

```go
type error interface {
    Error() string
}
```

Любой тип с методом `Error() string` автоматически становится ошибкой — без `implements`. Нулевое значение `error` — `nil`: «ошибки нет».

## Паттерн `(T, error)`

Функции, которые могут «упасть», обычно возвращают ошибку **последним** результатом. Успех — `nil`, неуспех — конкретный `error`:

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil
}

result, err := divide(10, 2)
if err != nil {
    // обработать: вернуть выше, залогировать, показать пользователю
    return err
}
// здесь result можно использовать
```

Так сбои явны в сигнатуре. На собесе часто спрашивают «почему не exceptions?» — ответ: ошибки видны в API, их передают как данные, контроль у вызывающего.

## Как создать ошибку

Базово:

```go
errors.New("cannot Sqrt negative number")
fmt.Errorf("user %s not found", name)
```

Свой тип ошибки — struct (или named type) с методом `Error()`. В упражнении тура:

```go
type ErrNegativeSqrt float64

func (e ErrNegativeSqrt) Error() string {
    return fmt.Sprintf("cannot Sqrt negative number: %v", float64(e))
}
```

Нюанс из тура: внутри `Error()` нельзя печатать `e` напрямую через `fmt.Sprint(e)` — `fmt` снова вызовет `Error()`, получится бесконечная рекурсия. Сначала приведи к другому типу, например `float64(e)`.

## Nil-ловушка

`error` — интерфейс, внутри пара `(тип, значение)`:

```go
var p *MyError = nil
var err error = p
fmt.Println(err == nil) // false
```

Интерфейс `nil`, только если и тип, и значение nil. Наружу возвращай обычный `nil`, а не typed nil pointer.


Ошибку часто **оборачивают** контекстом, не теряя причину:

```go
if err != nil {
    return fmt.Errorf("read config: %w", err)
}
```

Потом проверяют цепочку:

```go
errors.Is(err, ErrNotFound) // та же sentinel-ошибка?
var e *MyError
errors.As(err, &e)          // есть ли нужный тип?
```

Сравнивать по тексту (`err.Error() == "..."`) — плохая идея: текст для людей, для логики — `Is`/`As` или свой тип.

`panic` — не замена `error`. Ожидаемые сбои (файл не найден, плохой ввод) возвращают `error`. Panic — для «программа в неконсистентном состоянии».
