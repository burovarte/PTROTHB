Карта конспектов и порядок повторения. Финальный редакторский проход: **8 сентября 2026**. Проверены все **28 ранее существовавших Markdown-конспектов**; добавлены семь тем, теперь здесь 35 конспектов и это оглавление. Картинка планировщика — отдельный материал, не ещё один конспект.

## Проверка готовности без подсказки

| Сценарий | Что должно прозвучать в ответе |
|---|---|
| `append` изменил другой slice | Общий backing array, capacity, когда нужна копия |
| Интерфейс не равен nil | Динамический тип + значение, typed nil |
| Consumer pipeline вышел раньше | Отмена всех блокирующих send/receive и ожидание завершения |
| SQL замедлился при росте нагрузки | План/индекс, блокировки, пул и его ожидание; не просто «добавить соединений» |
| Два запроса списывают последний товар | Атомарное условное UPDATE или короткая транзакция с lock; проверить результат |
| Событие обработалось дважды | Ack/commit после эффекта, окно повтора и атомарная дедупликация |
| После UPDATE кеш вернул старое | Гонка наполнения, commit перед инвалидацией, TTL и требования к согласованности |
| Внешний API завис | Дедлайн, bounded retry с jitter, идемпотентность, breaker и лимит ресурсов |
| Во время deploy обрываются запросы | Readiness, graceful shutdown, время снятия маршрутов, совместимость схемы |
| p95 растёт, среднее почти нет | Хвост задержек; метрики → trace → конкретная зависимость/профиль |

## Что ещё нужно отработать руками

Конспекты не являются полной заменой следующих частей подготовки:

- **Алгоритмы и live coding:** hash map/set, stack/queue, binary search, two pointers, sliding window, базовый обход дерева/графа; оценка времени и памяти, граничные случаи. Используй отдельную папку `algorithms/`, здесь не дублируем её задачи.
- **SQL:** написать JOIN, агрегацию, оконную функцию и keyset pagination; объяснить индекс по реальному плану.
- **Мини-сервис:** endpoint плейлистов, PostgreSQL, timeout, cache-aside, тесты и метрики. По очереди выключить Redis/БД и объяснить поведение.
- **Linux и Git:** процессы/потоки, сигналы TERM/KILL, файловые дескрипторы и права; посмотреть порт и логи; объяснить branch/merge/rebase, разрешение конфликтов и revert. `kill -9` не даёт процессу корректно завершиться; rebase переписывает историю, revert создаёт обратный commit.
- **System design:** сначала требования и нагрузка, затем API/данные/компоненты, узкие места и отказы. Микросервисы и несколько БД не обязательны для маленькой задачи.
- **Рассказ об опыте:** какую проблему решал, почему выбрал подход, какие были компромиссы, как проверил результат. Не приписывать себе чужую работу.

Перед конкретным интервью уточни формат у рекрутера: глубина алгоритмов, SQL, system design и инфраструктуры отличается даже между командами одной компании.

В частности: recover и typed nil, range по версиям Go, правила errgroup, GOMAXPROCS/GC, SQL-проверки и пул, гонки кеша, подтверждения брокеров, безопасность и завершение контейнера.
