# Функции

Функция в Go — именованный блок кода с параметрами и (опционально) результатами. Тип пишется **после** имени параметра. Функция может принимать ноль или больше аргументов и возвращать ноль или больше значений.

```go
func add(x int, y int) int {
    return x + y
}
```

Если подряд идут параметры одного типа, тип можно указать один раз в конце:

```go
func add(x, y int) int {
    return x + y
}
```

Вызов обычный: `add(3, 4)`. Неиспользованный результат часто игнорируют через `_`, особенно второй результат-ошибку, когда сознательно её отбрасывают (на собесе лучше почти никогда так не делать с `error`).

## Несколько результатов

Функция может вернуть любое число значений — это одна из самых узнаваемых черт Go:

```go
func swap(x, y string) (string, string) {
    return y, x
}

a, b := swap("hello", "world")
```

Самый частый паттерн на практике и на собесе — `(T, error)`: полезный результат и ошибка последним значением. Успех — `err == nil`.

Пример:

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil
}

func main() {
    result, err := divide(10, 2)
    if err != nil {
        fmt.Println("ошибка:", err)
        return
    }
    fmt.Println("результат:", result) // 5

    result, err = divide(10, 0)
    if err != nil {
        fmt.Println("ошибка:", err) // деление на ноль
        return
    }
    fmt.Println("результат:", result)
}
```

## Именованные возвраты и naked return

Результаты можно **именовать**. Тогда они становятся переменными в начале функции (с zero value) и служат документацией: что именно возвращается.

```go
func split(sum int) (x, y int) {
    x = sum * 4 / 9
    y = sum - x
    return // naked return — вернёт текущие x и y
}
```

`return` без аргументов называется **naked return**: возвращаются именованные результаты как есть. В туре прямо сказано: так удобно только в **коротких** функциях; в длинных читаемость падает. На собесе хороший ответ: «именую, когда имена реально поясняют (`n, err`), naked return — редко и только в коротких штуках».

Именованные возвраты ещё стыкуются с `defer`: отложенная функция может поменять `err` / `result` перед фактическим выходом (это уже тема defer).

## Функции как значения

В Go функции — first-class values: их можно класть в переменные, передавать аргументом и возвращать из других функций.

```go
func compute(fn func(float64, float64) float64) float64 {
    return fn(3, 4)
}

hypot := func(x, y float64) float64 {
    return math.Sqrt(x*x + y*y)
}

fmt.Println(hypot(5, 12))
fmt.Println(compute(hypot))
```

## Замыкания (closures)

Анонимная функция может захватывать переменные из внешней области видимости. Такие переменные «живут» вместе с замыканием:

```go
func adder() func(int) int {
    sum := 0
    return func(x int) int {
        sum += x
        return sum
    }
}

pos, neg := adder(), adder()
fmt.Println(pos(1), neg(-2)) // у каждого своё состояние sum
```

## Variadic-параметры

Функция может принять переменное число аргументов одного типа через `...T`. Внутри это слайс:

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)
sum(a...) // распаковать существующий слайс
```

`fmt.Println` как раз variadic. На собесе часто рядом спрашивают отличие `nums ...int` в сигнатуре и `a...` при вызове.

## Что помнить для собеса

Тип после имени; несколько возвратов — норма; `(result, error)` — идиома; именованные возвраты документируют смысл, naked return — только в коротких функциях; функции можно передавать как значения; замыкание хранит состояние внешней области. Обычные ошибки — через `error`, не через panic.

Короткая фраза: «Функция в Go может вернуть несколько значений; ошибки отдаём последним `error`; функции — значения, замыкания захватывают окружение».
