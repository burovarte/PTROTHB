# Дженерики в Go

Дженерики — механизм, который позволяет переиспользовать код через параметризацию типов. Их добавили в язык в 2022 году (Go 1.18).

## Как проектировали дженерики

При разработке рассматривали два подхода.

**Stenciling** (как в C++ и Rust) — для каждого типа генерируется свой код. Плюсы: высокая производительность. Минусы: медленная компиляция и большой размер бинарного файла.

**Dictionaries** — создаётся один набор кода и словарь типов. Плюсы: быстрая компиляция, нет раздувания файла. Минусы: накладные расходы во время выполнения.

Go выбрал компромисс: моноформизацию для типов с одинаковой формой памяти и словарь для информации о типах во время выполнения. Из‑за этого остаются некоторые runtime-накладные расходы.

## Синтаксис и основные элементы

Дженерики используют три ключевых элемента:

- **формальный параметр типа** (например, `T`) — конкретный тип зависит от переданного значения;
- **ограничение типа / constraint** (например, `int | float64`) — задаёт допустимые типы для параметра;
- **фактический параметр типа** — указывается явно (`Sum[int](1, 2)`) или выводится компилятором (`Sum(3.14, 1.11)`).

С дженериками можно создавать:

- generic-срезы;
- хэш-таблицы;
- структуры;
- интерфейсы.

Пример функции сложения:

```go
func Sum[T int | float64](a, b T) T {
    return a + b
}
```

Если подходит **любой** тип, пишут constraint `any`:

```go
func Print[T any](v T) {
    fmt.Println(v)
}
```

`any` = «без ограничений» (то же, что раньше `interface{}`).

### Важно про `T any`

С `T any` внутри функции можно делать только то, что можно с **любым** типом:

- положить в переменную;
- передать дальше;
- вернуть.

**Нельзя** просто так:

- сравнивать `v == x` → нужен `comparable`;
- складывать `a + b` → нужен числовой constraint вроде `int | float64`;
- вызывать метод `v.Read(...)` → нужен интерфейсный constraint, например `io.Reader`.

## Особенности и ограничения

У дженериков в Go есть важные ограничения:

- нельзя использовать дженерик как базовый тип;
- нельзя сделать type assertion для параметра типа так же свободно, как для обычного интерфейса;
- анонимные структуры и функции не поддерживают дженерики;
- методы не могут иметь собственные type parameters (хотя receiver generic-типа — можно);
- type set / множества типов нельзя напрямую передать как фактический параметр типа.

Есть нюансы работы с множествами типов: правила объединения и пересечения, а также символ `~` для обозначения underlying type (базового типа).

## Практическое применение

Чаще всего дженерики применяют для структур данных.

**Очередь** — тип элементов может быть любым (`any`). Методы вроде `Push`, `Pop`, `Peek`, `Size`.

**Куча (heap)** — элементы должны быть сравнимы/сортируемы. При инициализации часто нужен пользовательский компаратор.

**Пул объектов** — с дженериками не требуется type assertion при извлечении объекта.

## Влияние на компиляцию

Добавление дженериков замедлило компиляцию — это компромисс, на который пошла команда Go. Цель — сохранить удобство языка, даже если нагрузка на компилятор выросла.
