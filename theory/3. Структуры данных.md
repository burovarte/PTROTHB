# Структуры данных

В Go «структуры данных» на уровне языка — это в первую очередь `struct`, `array`, `slice` и `map`.

## Struct

`struct` — набор полей. Это способ собрать связанные данные в один тип:

```go
type Vertex struct {
    X int
    Y int
}

v := Vertex{1, 2}
fmt.Println(v.X)
```

Поля читают и пишут через точку. Можно брать указатель на структуру: `p := &v`, а дальше писать `p.X` — Go сам разыменует. Литералы удобны с именами полей: `Vertex{X: 1, Y: 2}`. Zero value у struct — структура, где каждое поле в своём zero value.

Struct — value type: присваивание и передача в функцию копируют поля. Поэтому для мутации и больших объектов часто передают `*Struct`.

## Array

Тип `[n]T` — массив из `n` элементов типа `T`. Размер — часть типа: `[10]int` и `[20]int` — разные типы. Длина фиксирована, массив нельзя увеличить.

```go
var a [2]string
a[0] = "Hello"
a[1] = "World"

primes := [6]int{2, 3, 5, 7, 11, 13}
```

На практике массивы встречаются реже слайсов: они нужны, когда размер известен заранее и важен как часть типа, либо как базовое хранилище для слайса.

## Slice

Slice — динамический гибкий вид на элементы массива.

Срез задаётся полуинтервалом `a[low:high]` — `low` включается, `high` нет:

```go
primes := [6]int{2, 3, 5, 7, 11, 13}
s := primes[1:4] // [3 5 7]
```

Slice не хранит элементы сам — он описывает участок **базового массива** (по-английски underlying array). Изменение элементов слайса меняет этот массив; другие слайсы на тот же массив это видят. У слайса есть **длина** (`len`) — сколько элементов доступно сейчас, и **вместимость** (`cap`) — до какой длины слайс можно расширить без создания нового массива.

Zero value слайса — `nil`: `len == 0`, `cap == 0`. С `nil` slice можно безопасно делать `len`, `range`, `append`. Создают слайс литералом, срезом массива или через `make`:

```go
a := make([]int, 5)    // len=5, cap=5
b := make([]int, 0, 5) // len=0, cap=5
```

`append` добавляет элементы. Если вместимости не хватает, он создаёт новый базовый массив и копирует туда старые элементы. `copy` копирует элементы между слайсами. Обход — `for i, v := range s`.

### `append`

`append` возвращает новый слайс — смотрящий на прежний или уже на новый базовый массив. Результат нужно сохранить:

```go
s := []int{1, 2, 3}

s = append(s, 4)              // [1 2 3 4]
s = append(s, 5, 6)           // [1 2 3 4 5 6]
s = append(s, []int{7, 8}...) // распаковка другого слайса
```

`nil` slice тоже ок:

```go
var s []int
s = append(s, 1) // [1]
```

Если `cap` хватает — элементы пишутся в тот же базовый массив.

Если нет — выделяется новый массив побольше, старые элементы копируются туда, и слайс начинает смотреть уже на него.

### Алиасинг и ограничение вместимости

**Алиасинг** — ситуация, когда две переменные дают доступ к одним и тем же данным в памяти. У слайсов это происходит, когда они смотрят на один базовый массив. Поэтому изменение через один слайс может быть видно через другой:

```go
base := []int{1, 2, 3, 4}
// индекс:      0  1  2  3

a := base[:2]  // элементы с индексов [0:2): [1 2], len=2, cap=4
b := base[1:3] // элементы с индексов [1:3): [2 3], len=2, cap=3

a = append(a, 99) // новый элемент пишется после a[1], то есть в base[2]

fmt.Println(base) // [1 2 99 4]
fmt.Println(a)    // [1 2 99]
fmt.Println(b)    // [2 99]: b тоже видит изменённый base[2]
```

### Трёхиндексный срез

Обычный срез записывается как `s[low:high]`. **Трёхиндексный срез** (full slice expression) записывается как:

```go
s[low:high:max]
```

Третий индекс `max` ограничивает вместимость нового слайса:

```text
len = high - low
cap = max - low
```

Это позволяет запретить `append` перезаписывать соседние элементы старого массива:

```go
base := []int{1, 2, 3, 4}
a := base[0:2:2] // low=0, high=2, max=2 → len=2, cap=2

// В a уже находятся 2 элемента, и его вместимость тоже равна 2.
// Свободных мест нет: len(a) == cap(a).
a = append(a, 99) // нужен третий элемент → создаётся новый базовый массив

fmt.Println(base) // [1 2 3 4]: прежний массив не изменился
fmt.Println(a)    // [1 2 99]: a теперь смотрит на новый массив
```

Без третьего индекса `base[:2]` получил бы `len=2`, но `cap=4`: после двух видимых элементов оставались бы ещё два места базового массива. В варианте `base[:2:2]` мы сами ограничили `cap` числом `2`, поэтому `append` обязан выделить новый массив.

Ещё одна практическая ловушка: маленький подслайс удерживает целиком большой базовый массив. Если нужно оставить небольшой фрагмент надолго, его иногда стоит скопировать в новый слайс.

### Устройство slice

Концептуально значение slice — небольшой заголовок из трёх частей:

```text
указатель на базовый массив
длина (len)
вместимость (cap)
```

При передаче slice в функцию копируется этот заголовок, но элементы обычно остаются общими:

```go
func change(s []int) {
    s[0] = 100
}

values := []int{1, 2, 3}
change(values)
fmt.Println(values) // [100 2 3]
```

Изменение элемента видно вызывающему, а изменение самого локального заголовка — нет:

```go
func appendWrong(s []int) {
    s = append(s, 4) // изменился локальный заголовок s
}

func appendRight(s []int) []int {
    return append(s, 4)
}
```

Точный коэффициент роста вместимости является деталью реализации runtime. Нельзя строить логику на предположении, что `cap` всегда удваивается. Если примерный размер известен, заранее выдели вместимость:

```go
result := make([]Item, 0, expectedCount)
```

### Удаление элементов

Удаление без сохранения порядка:

```go
s[i] = s[len(s)-1]
var zero T
s[len(s)-1] = zero // для ссылочных элементов не удерживать удалённый объект
s = s[:len(s)-1]
```

Удаление с сохранением порядка:

```go
copy(s[i:], s[i+1:])
var zero T
s[len(s)-1] = zero // не удерживать ссылочный объект
s = s[:len(s)-1]
```

Обнуление удалённого элемента важно для slice указателей или больших объектов со ссылочными полями: иначе базовый массив может продолжать удерживать уже ненужные данные от GC.

### `copy`

`copy(dst, src)` копирует `min(len(dst), len(src))` элементов и возвращает, сколько скопировал:

```go
src := []int{1, 2, 3, 4, 5}
dst := make([]int, 3)

n := copy(dst, src)
fmt.Println(n, dst) // 3 [1 2 3]
```

Чтобы скопировать слайс целиком в новый независимый:

```go
src := []int{1, 2, 3}
dst := make([]int, len(src))
copy(dst, src)

dst[0] = 100
fmt.Println(src) // [1 2 3] — не изменился
fmt.Println(dst) // [100 2 3]
```

## Map

Map — отображение ключ → значение (хеш-таблица). Ключи должны быть comparable (нельзя ключом сделать slice, map, function).

```go
m := make(map[string]int)
m["Answer"] = 42

v, ok := m["Answer"] // ok == false, если ключа нет
delete(m, "Answer")
```

Zero value map — `nil`. У `nil` map нет ключей, и добавлять в неё нельзя (panic). Поэтому перед записью нужен `make` или литерал:

```go
m := map[string]Vertex{
    "Bell Labs": {40, -74},
    "Google":    {37, -122},
}
```

Добавление или обновление элемента:

```go
m[key] = elem
```

Получение элемента:

```go
elem = m[key]
```

Удаление элемента:

```go
delete(m, key)
```

Проверка наличия ключа с помощью присваивания с двумя значениями:

```go
elem, ok = m[key]
```

Если ключ есть в `m`, `ok` будет `true`. Если нет — `false`, а `elem` будет нулевым значением для типа элемента мапы.

Порядок обхода `map` не гарантирован. Обычная map также не предназначена для конкурентной записи или одновременных чтения и записи без синхронизации: используют `Mutex`, `RWMutex`, `sync.Map` в подходящих сценариях или одного владельца состояния.

### Map глубже

Map — ссылкоподобный дескриптор runtime-структуры. При передаче map в функцию копируется дескриптор, но обе копии обращаются к одной таблице:

```go
func put(m map[string]int) {
    m["answer"] = 42
}
```

При добавлении элементов map может расти и постепенно переносить данные во внутренние новые области. Это деталь runtime, поэтому нельзя полагаться на расположение элементов или порядок обхода.

Элемент map нельзя взять по адресу:

```go
type User struct{ Age int }
m := map[string]User{"ann": {Age: 20}}

// m["ann"].Age++ // ошибка компиляции

u := m["ann"]
u.Age++
m["ann"] = u
```

Причина: при росте map элемент может перемещаться, поэтому язык не выдаёт стабильный указатель на ячейку. Альтернатива — хранить указатели:

```go
m := map[string]*User{"ann": {Age: 20}}
m["ann"].Age++
```

Операция чтения отсутствующего ключа возвращает zero value. Поэтому для различения «ключ отсутствует» и «ключ есть со значением zero» используют comma-ok:

```go
value, ok := m[key]
```

На собеседовании важно разделять:

- конкурентные чтения без записи допустимы;
- конкурентная запись или чтение одновременно с записью требуют синхронизации;
- `sync.Map` не является автоматической заменой `map + Mutex`, а оптимизирован для отдельных сценариев.

Если `elem` или `ok` ещё не объявлены, можно использовать краткую форму:

```go
elem, ok := m[key]
```

## Что дополнительно знать на middle

- Доступ по индексу slice — O(1); поиск в неотсортированном slice — O(n); append — амортизированно O(1), но с переносом массива O(n).
- Поиск в map — в среднем O(1), это не гарантия постоянного времени для любого входа.
- Массивы и структуры сравнимы, если сравнимы все элементы/поля. Slice/map/function сравнивают только с `nil`; для содержимого нужны отдельные операции.
- `nil` и пустой slice имеют длину 0, но `encoding/json` обычно кодирует их как `null` и `[]` соответственно.
- В Go 1.24 встроенная map перешла на Swiss Tables. Старое описание bucket/overflow относится к прежнему runtime; детальную раскладку не нужно выдавать за контракт языка.
