# Defer, panic, recover

В обычном потоке Go хватает `if` / `for` / `switch`. Рядом с ними стоят три специальных механизма: **`defer`** откладывает вызов на выход из функции, **`panic`** аварийно рвёт обычное выполнение, **`recover`** может эту панику поймать. На собесе их почти всегда спрашивают вместе.

## Defer

Оператор `defer` откладывает выполнение функции до момента выхода из текущей функции.

Отложенные вызовы помещаются в стек. При возврате из функции они выполняются в порядке **LIFO** («последним пришёл — первым ушёл»).

`Defer` нужен для освобождения ресурсов: закрыть файл, закрыть подключение к БД, разблокировать mutex. Это гарантирует, что ресурс будет освобождён даже при досрочном `return`. `defer` выполняется всегда перед выходом из функции — через `return`, конец тела или из-за `panic`.

Аргументы вычисляются **сразу** в момент объявления `defer`, а сам вызов откладывается.

Классический пример — cleanup рядом с открытием ресурса:

```go
f, err := os.Open(name)
if err != nil {
    return err
}
defer f.Close()

// дальше работаем с f
```

Так `Close` не забудешь на каждом `return`. То же для `mutex.Unlock()`, отмены context, закрытия ответа HTTP.

Несколько `defer` складываются в стек и выполняются в порядке LIFO (последний отложенный — первый выполненный):

```go
func main() {
    fmt.Println("counting")

    for i := 0; i < 3; i++ {
        defer fmt.Println(i)
    }

    fmt.Println("done")
}

// counting
// done
// 2
// 1
// 0
```

Частая ловушка с циклом и замыканием: `defer` с функцией, которая читает переменную цикла, может увидеть уже финальное значение — поэтому аргументы лучше передавать явно (`defer func(i int){ ... }(i)`), как и с горутинами.

Ещё нюанс для собеса: `defer` может менять **именованные** возвращаемые значения:

```go
func double(x int) (result int) {
    defer func() { result *= 2 }()
    return x
}
```

## Panic

`panic` — аварийное завершение выполнения текущей goroutine. После этого программа завершится, если никто не перехватит панику.

`panic` останавливает обычный поток. Выполнение текущей функции обрывается, её deferred-вызовы всё равно отрабатывают, затем panic «всплывает» к вызывающему — и так вверх по стеку горутины. Если никто не сделал `recover`, программа падает со стектрейсом.

Панику вызывают явно:

```go
panic("что-то пошло совсем не так")
```

или получает runtime: выход за границы слайса, разыменование `nil`, деление целых на ноль и т.п.

Важно: **`panic` — не замена `error`**. Ожидаемые сбои (файл не найден, плохой ввод, сеть недоступна) возвращают `error`. Panic — для ситуаций «программа в неконсистентном состоянии» или глубоких внутренних инвариантов, которые снаружи всё равно превращают в `error` (так, например, внутри делает часть пакета `encoding/json`).

## Recover

`recover` позволяет перехватить `panic`, но работает **только внутри `defer`**.

Он останавливает панику и возвращает значение, которое передали в `panic` (тип `any` / `interface{}`). Вне `defer` почти всегда вернёт `nil` и ничего не сделает.

```go
func safe() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("поймали:", r)
        }
    }()

    panic("бум")
}
```

После успешного `recover` выполнение продолжается с места **после** deferred-функции (обычно это выход из окружающей функции), а не с места, где был `panic`. Поймать panic из **другой** горутины нельзя: у каждой горутины свой стек.

Типичные места `recover` на практике: обёртка вокруг HTTP-handler / воркера, чтобы одна паника не уронила весь процесс; граница пакета, где внутренний panic превращают в `error` для вызывающего.

Паттерн «panic внутри → error снаружи»:

```go
func Parse(input string) (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("parse failed: %v", r)
        }
    }()

    // глубокая логика, которая может panic
    return nil
}
```

## Как это связать одной картинкой

Сначала ставишь `defer` на cleanup. Если случился `panic`, deferred-функции всё равно бегут (и там же можно сделать `recover`). Если `recover` не вызвали — горутина умирает, часто вместе с программой. Для обычных ошибок по-прежнему `if err != nil`.
