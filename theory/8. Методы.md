# Методы

В Go нет классов, но у типов есть **методы**. Метод — это функция со специальным аргументом **receiver** (получателем). Receiver стоит между `func` и именем метода и связывает функцию с типом.

```go
type Vertex struct{ X, Y float64 }

func (v Vertex) Abs() float64 {
    return math.Sqrt(v.X*v.X + v.Y*v.Y)
}

v := Vertex{3, 4}
fmt.Println(v.Abs())
```

По смыслу это почти обычная функция `Abs(v Vertex) float64`, но вызывается как `v.Abs()` и входит в **method set** типа — а значит участвует в реализации интерфейсов.

Методы объявляют на **именованных** типах того же пакета (не только на struct: можно `type MyFloat float64`). Нельзя добавить метод к built-in типу напрямую и нельзя к типу из другого пакета — тогда делают обёртку `type MyTime time.Time`.

## Value receiver vs pointer receiver

**Value receiver** — `(v Vertex)`: метод получает **копию**. Изменения полей снаружи не видны.

**Pointer receiver** — `(v *Vertex)`: метод работает с оригиналом, может менять состояние.

```go
func (v *Vertex) Scale(f float64) {
    v.X = v.X * f
    v.Y = v.Y * f
}

v := Vertex{3, 4}
v.Scale(10)
fmt.Println(v) // {30 40}
```

Есть две причины брать pointer receiver:

1. нужно **изменить** receiver;
2. не хочется **копировать** большой struct на каждый вызов.

Pointer receivers в реальном коде встречаются чаще. Правило тура: у одного типа лучше **не смешивать** — либо почти все методы на `*T`, либо на `T`. Иначе method set «разъезжается» и с интерфейсами будет боль.

## Синтаксический сахар при вызове

Компилятор помогает при обычном вызове:

- есть `v` типа `T` и метод на `*T` → вызовет `(&v).Method()`, если `v` **addressable**;
- есть `p *T` и метод на `T` → вызовет `(*p).Method()`.

Поэтому `v.Scale(10)` работает даже для pointer-метода. Но не всё addressable: литерал `Vertex{}.Scale(...)`, элемент map, значение внутри интерфейса — адреса может не быть, и авто-`&` не сработает.

## Методы и nil

Метод можно вызвать на `nil` pointer — паники на самом вызове не будет, пока не тронешь поля. Иногда пишут nil-safe методы:

```go
func (c *Conn) Close() error {
    if c == nil {
        return nil
    }
    // ...
    return nil
}
```

## Как выбирать receiver — ответ на собес

Мутация / большой тип / консистентность с другими методами / нужен `*T` в интерфейсе → **pointer**.  
Маленький immutable-подобный тип, только чтение → можно **value**.  
Главное — единообразие на типе.

Короткая формула: «метод = функция + receiver; pointer — чтобы менять и не копировать; method set решает, подойдёт ли тип в интерфейс».
